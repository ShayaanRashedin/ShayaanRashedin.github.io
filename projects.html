FPGA Cache Controller

View source ↗

Write-back cache in VHDL

Designed and integrated a 256-byte direct-mapped cache on a Xilinx Spartan-3E FPGA. A 13-state controller handles read and write hits, block refill, and dirty-block write-back.

VHDLSpartan-3EBRAMChipScope
  1. 01CPU requestCapture address, operation and byte
  2. 02Cache decisionTag + valid → hit or replacement
  3. 03Memory transferSave dirty block → refill → complete

Engineering decisions

01

Eight slots, 32 bytes each

Split the 16-bit CPU address into tag, index and offset, with valid and dirty metadata per cache block.

02

Preserve modified data

Write-back uses the old stored tag before refill uses the new requested tag. A byte counter sequences each 32-byte block transfer.

03

Clocked memory sequencing

Separate setup, strobe and capture states satisfy the synchronous BRAM and backing-memory interfaces.

Hardware testing & timing

Used ChipScope ILA captures and VIO controls to exercise four cache cases. At 50 MHz, the project report records 60 ns write hits, 80 ns read hits, 2020 ns clean read misses and 3920 ns dirty write misses. These are report measurements; the hardware run has not been independently repeated.

Implementation details
Scope & attribution

The CPU transaction generator was supplied for the course. The SDRAM-named module is an 8 KB FPGA backing-memory model, with 13-bit physical addressing, rather than an external SDRAM controller. Xilinx generates the memory and debug cores. Source and configuration files are published with attribution.

01 / LINUX SYSTEMS

SyncWire

View repository ↗

Resumable TCP file transfer

SyncWire is a C++20 client-server application for file uploads and incremental directory synchronization over TCP. It implements message framing, interrupted-transfer recovery, and verified file commits.

C++20 POSIX TCP / epoll
  1. 01 Client CLI Manifest + framed messages
  2. 02 Server workers epoll → bounded queue
  3. 03 Verified storage Partial data → atomic rename

Engineering decisions

01

Explicit framing

A versioned 32-byte header, request IDs, bounded payloads, and incremental parsing handle partial reads and coalesced messages.

02

Interrupted-transfer recovery

Saved offsets and prefix checksums let interrupted uploads reuse verified bytes, including after a server restart.

03

Bounded concurrency

A worker pool handles sessions while destination mutations are serialized to protect filesystem state.

Implementation & validation

The repository includes CTest coverage, real TCP interruption and restart acceptance tests, and Debug, Release, ASan, and UBSan CI configurations. The acceptance script compares output files using SHA-256.

Recovery acceptance script ↗ Protocol & integration tests ↗
Scope & tradeoffs

One-way push over loopback. HMAC authenticates peers but does not encrypt file data or authenticate later frames. CRC-32 detects accidental corruption; directory sync commits files individually.

02 / NETWORK OBSERVABILITY

NetWatch

View repository ↗

Linux network observability

NetWatch collects Linux socket information, correlates connections with processes, and stores lifecycle events and rule-based alerts in SQLite. A read-only API and dashboard expose the recorded data.

C++20 Linux procfs SQLite
  1. 01 Linux procfs Collect sockets + processes
  2. 02 Detection pipeline Compare → queue → SQLite
  3. 03 Read-only API Events + alerts → dashboard

Engineering decisions

01

Process identity tracking

PID and process start time are tracked together so reused PIDs do not combine unrelated activity.

02

Collection and storage are separate

A bounded producer-consumer queue and background writer make persistence pressure explicit.

03

Alert reasons and supporting evidence

Each rule produces severity, reasons, and supporting evidence. Events and their alerts are stored in one transaction.

Dashboard preview

Implementation & validation

The repository includes Catch2/CTest coverage for parsing, process resolution, snapshot comparison, detection, queue behaviour, storage, and API services, plus installation and container checks.

Scope & tradeoffs

Periodic snapshots can miss short-lived connections. Visibility depends on Linux permissions. Heuristic alerts support investigation, not a conclusion of malicious activity. The unauthenticated API defaults to loopback.

03 / EMBEDDED · TEAM PROJECT

EEBOT Robot Guidance

View repository ↗

Embedded robot navigation

A mobile robot must turn noisy sensor readings into reliable movement: follow tape, choose branches, recover from dead ends, and retrace recorded decisions. This shared COE538 project was developed with Hamidullah Mohmmad Ali and Daniel Chylek.

Assembly GPIO / ADC State machines
  1. 01 Sense 5 infrared channels + bumpers
  2. 02 Decide State machine + route memory
  3. 03 Act Motors + LCD feedback

Engineering decisions

01

Modular firmware structure

Sensing, motor helpers, route routines, and display updates are kept distinct so physical behaviour is easier to debug.

02

Fixed-size route memory

Fixed-size route arrays record arrival, departure, and alternative headings for up to 32 junctions or corners.

03

Timer interrupts and LCD feedback

Timer-overflow interrupts and live LCD feedback support steering calibration, navigation timing, and fault diagnosis.

Python Security Automation

Network Threat Detector

Python CSV Parsing SQLite Airflow

Network Threat Detector is a Python command-line tool that analyzes custom and Wireshark-exported network logs, flags suspicious patterns, and saves structured findings for review. It demonstrates modular Python, deterministic detection, persistent records, and repeatable security-automation workflows. Scope: It analyzes exported logs rather than live packet captures, and rule-based findings do not establish malicious activity.

Engineering Highlights

  • Separated CSV ingestion, detection rules, presentation, SQLite persistence, and workflow orchestration into focused modules.
  • Implemented explainable rules for possible port scanning, suspicious outbound connections, exfiltration indicators, and beaconing.
  • Automated repeatable execution with Bash and an optional Apache Airflow DAG backed by a local Docker Compose workflow.

Linux VirtualBox Nmap / GVM Splunk

The Cybersecurity Homelab is an isolated VirtualBox environment for investigating Linux services, network exposure, vulnerabilities, and authentication logs.
